# Формат карточки задачи

Одна задача — один файл `problems/<глава>/<номер>.md`. Шаблон: [`templates/zadacha.md`](../templates/zadacha.md).

## Заголовок (YAML)

```yaml
---
id: "00.05-004"          # ГГ.ПП-NNN (или NNNN), совпадает с именем файла
chapter: 0               # 0 — Введение, 1–14 — главы, 15 — Приложение, 16 — координаты, 17 — смешанные
section: 5               # параграф (0 — если параграфов нет)
level: 3                 # ступень 1–10
type: A                  # код типа: R T A V C D P M K S F E I (E — диагностика)
step: iso                # complete | iso | vary | open | transfer | mixed
condition: def           # def | alt | under | over
form: sym                # sym | nat | meta
answer: short            # short | proof | build | text
source: "с. 8, D3"       # страница и пункт книги, на которые опирается решение
system: null             # например "S^1", если задача в рамках системы
case: null               # classical | nonclassical | null
series: null             # имя серии для однотипных упражнений
tags: [главный оператор]
---
```

Обязательные поля: `id`, `chapter`, `section`, `level`, `type`, `form`, `answer`. Поле `source` обязательно для всех задач, кроме смешанных наборов (раздел 17). Поля `step` и `condition` необязательны, но желательны.

## Тело

```markdown
## Условие

Текст задачи.

<details><summary>Подсказка</summary>

Необязательная подсказка.

</details>

## Ответ

<details><summary>Показать ответ</summary>

Короткий ответ.

</details>

## Решение

<details><summary>Показать решение</summary>

Решение со ссылками на определения, аксиомы и страницы книги.

</details>
```

Разделы «Условие», «Ответ» и «Решение» обязательны. Для задач ступени 10 в «Ответе» пишутся критерии хорошего решения, в «Решении» — эскиз одного из решений.

В диагностической задаче (тип E) ответ обязательно называет нарушенное правило: обозначение из книги (D, A, R, MT с номером) и страницу.

## Требования к содержанию

1. Решение опирается только на книгу (для раздела 16 — на указанные в нём источники). Каждое использованное определение, аксиома или правило названо так, как в книге (D2, A7, R3, MT1…), и в `source` указана страница.
2. Обозначения — строго по [04-oboznacheniya.md](04-oboznacheniya.md).
3. Вывод оформляется как в книге: шаги пронумерованы, справа в квадратных скобках — основание шага.
4. Если задача выходит за пределы книги (ступень 10, тип I), это сказано в условии.

## Проверка

```bash
python3 scripts/validate.py   # формат, коды, уникальность номеров, квоты
python3 scripts/build.py      # пересобрать оглавления, индексы, прогресс
```

GitHub Actions выполняет обе проверки при каждом push.
